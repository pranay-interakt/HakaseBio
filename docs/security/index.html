Security and compliance

Built for regulated records.

BioSim is designed for regulated work: electronic records and signatures that follow 21 CFR Part 11, an audit trail where any rewrite is detected, and access limited to the people on each programme.

Signatures

People sign, and sign again.

The legal sign-offs in nonclinical work belong to people: the GLP Study Director, quality assurance, the IACUC or attending veterinarian and, for EU GMP release, the qualified person. BioSim assembles what they need and records their signature. It never signs on their behalf.

Every signature asks for the password again, as 21 CFR 11.200 requires. GLP approval needs both the Study Director and QA signatures on the current version of the report.

Audit trail

A record where any change shows.

Every change is an entry in an append-only, hash-chained ledger, written in the same transaction as the change itself, so any later rewrite breaks the chain and is detected. Rejected uploads are recorded too. Corrections create a new version linked to the old one, with a reason. Ledger checkpoints can be anchored to write-once storage.

Access

Each programme sees only its own.

A programme is visible only to its organisation and to guests added on the record, such as a contract lab. Exported bundles redact other programmes’ entries, and the chain still verifies. Session length, idle timeout and sign-in lockout are set by policy.

Deployment

Runs where your data needs to be.

BioSim ships as containers with PostgreSQL, with dependencies locked by hash and a software bill of materials for each build. Database migrations are versioned and can be run as a separate, controlled step.

Validation

What stays with you.

Computer system validation (IQ, OQ and PQ) and the SOPs for a regulated deployment are the deploying organisation’s step. We provide a clause-by-clause traceability matrix from Part 11, Part 58 and data-integrity expectations to the code and tests that implement them.
